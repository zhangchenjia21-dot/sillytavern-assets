# 通用资产库｜维护规范 v0.4

> [!summary]
> 目标不是让通用库越来越大，而是让它成为**稳定、可复用、Canonical Ownership 清晰，并且在大型组合下仍能被 Runtime 有界消费的机制资产层**。

---

# 1. 新资产先分类

任何新想法先判断：

- **Core**：拥有跨世界长期 Canonical Domain；
- **Gameplay / Framework**：在已有 Core 上形成可复用玩法闭环；
- **Theme**：依赖已有 Core，对某领域做增量语义深化；
- **World-specific**：离不开具体时代 / 地理 / 组织 / 历史事实，不进入通用库。

无法说明独立 Owner 的机制，优先作为 Contribution / Theme / Module。

---

# 2. Core-first / Shared Foundation

当多个 World-specific / Theme Consumer 需要同一底层机制时：

```text
Domain Survey
↓
Genericity / Shared Foundation
↓
Canonical Owner
↓
Generic Core
↓
Downstream / Theme
↓
World-specific Consumer
```

禁止先让多个消费者各自拥有临时事实源，最后再大规模抽 Core。

---

# 3. Canonical Owner / Authority

每类长期事实只有一个 Canonical Owner。

必须区分 Definition Contributor、Instance State Owner、Derived Projection、Reference / Read Model、Cache、UI Contributor。

Projection / cache 默认不可反写 Authoritative State。Aggregate State 与 Named Instance State 必须有 bridge，避免双计数。

---

# 4. 关系必须类型化

正式关系：Hard Dependency、Optional Integration、Feature / Module Conditional Dependency、Provider → Consumer、Handoff、Contribution、Reference / Read-only。

禁止模糊 `dependency`、Hard Cycle 和 fallback second owner。

正式冻结：**Dependency Graph != Context Inclusion Graph。**

依赖表示语义 / 权威 /组合关系，不代表模型上下文必须全文包含上游。

---

# 5. World Consumer 不反向污染 Generic Asset

首发世界可以提供 reference consumer、world-specific example、compatibility note；不能把世界专名、历史人物、神名、地理、专用组织写进 Generic Core Canonical Mechanism。

`first consumer != generic owner`。

---

# 6. Runtime Context Contract

所有新 Core / 重要 Expansion 必须遵守：

```text
Asset Library != Game Enabled Asset Set != Current Runtime Relevant Set != Current Model Visible Working Set
Full Semantic Asset != Model Prompt Payload
```

Context Contract 采用 `[[通用资产库_RuntimeContextContract模式_v0.3]]`，至少回答：

1. Routing Profile；2. Immediate Activation；3. State-mandatory Activation；4. Downstream Activation；5. No-load；6. Minimal Read；7. Model-needed；8. Program-owned；9. Output Candidate；10. Handoff / Information Boundary；11. Context Cost；12. Feature / Module Hierarchy（如适用）；13. Background Program Progression（如适用）。

---

# 7. Model-first Semantic Routing

```text
Player Input
+ Enabled Routing Profiles
+ minimal current scene / active context
↓
Router Model
↓
immediate Domain / Intent candidates
↓
Program structural validation + state-mandatory augmentation
↓
JIT bounded projection
```

Program 不重复自然语言 Router；Router 不负责预测全部后果，后续通过 Formal Event / Typed Handoff 激活。Router miss 不得成为 Open Attempt 白名单。

---

# 7A. Background Progression / Feature-Module Gate

长期 Need / timer / cooldown / routine automation 若可 deterministic 推进：

```text
Background Runtime Progression != Model Activation
```

带 Feature / Module 的 Package 必须区分：

```text
Package Included != Feature Enabled != Module Enabled != Runtime Relevant != Model Visible
```

关闭 Feature / Module 不进入 Router Directory，不产生 Conditional Dependency，不显示其条件 Surface；已启用但当前无关的 Module 也不自动进入 Model Working Set。

---

# 8. Program Authority

资产 / 模型不得拥有 RNG / Dice、Program Judge、Formal Outcome、direct State Mutation、Atomic Commit、Save / Restore authority。

可 deterministic、安全、可测试的规则优先留在 Program，不为了“文档里写了规则”就放进模型 Working Set。

---

# 9. Information Boundary

后台 Truth != Player Knowledge != NPC Knowledge != Narrative Context。

每个 Context Contract 必须说明哪些 State 可读取、哪些只能 player-safe / npc-safe projection、哪些历史只给摘要。

---

# 10. UI Surface

新资产默认优先贡献：Core Surface Contribution → Entity Detail → Player Status / Detail → Contextual → Global Notice → Extension Surface。

一级 Extension Surface 只在形成长期独立工作空间时 owns；Owner 唯一。

---

# 11. Version Discipline

Patch：stale ref / metadata / dependency closure / Host wording / Context Contract retrofit，不改变 Owner。

Minor：新增重要机制 /状态 /合法语义，Owner 不变。

Major：Owner / Scope / topology 真正改变；必须 supersedes + migration + consumer audit + blueprint / matrix 同步。

---

# 12. Asset / Cluster / Library Audit

Asset Audit：单资产完成即执行。

Cluster Audit：2–5 个高耦合资产成簇后检查 duplicate owner、namespace、cycle、state mirroring、pairwise / transitive context explosion、Surface、Context Contract。

Generic Library Convergence 在新增 Core、Core 拆合、World-specific 提升 Generic、Owner/Surface/Context Architecture/G9 binding 变化时执行。

---

# 13. Context Composition Stress Test

G9 / Retrofit Convergence 至少测试 Typical / Heavy / Worst Reasonable Valid Bundle，覆盖普通无关 Turn、单 Domain、2–3 Domain、高耦合 Event、长期 Session。

目标：

```text
Enabled Assets ↑↑↑ → unrelated Turn context ≈ stable
Session Length ↑↑↑ → ordinary Turn context ≈ bounded
```

---

# 14. Existing Expansion Context Retrofit

旧资产按审计分类：ALREADY COMPLIANT / PATCH / MINOR / MAJOR / METADATA-WORKSPACE ONLY。

```text
Wave 1  Character / Relationship / Health / Combat / ORG recheck  ✓ PASS / CLOSED
Wave 2  Survival / Traveler-System                                ✓ PASS / CLOSED
Wave 3  Magic / Divine                                             NEXT
Wave 4  Combat Magic                                               PLANNED
```

全部完成后 Generic Library Context Convergence。

---

# 14A. Context Sidecar Governance

成熟旧资产若 Domain Semantics / Owner / Dependency / Handoff 均不变，允许唯一 Runtime Context Contract Sidecar：

- `canonical_domain_ownership: none`；
- 精确绑定 asset_id + asset_version；
- 不新增 gameplay semantics；
- 不覆盖 Canonical Asset Semantics；
- 一个 asset version 只有一个 current Contract source。

若 Audit 暴露真实语义缺陷，必须回正文修订。Canonical location 登记于 `[[通用资产库_RuntimeContextContract索引_v0.2]]`。

---

# 15. Periodic Architecture Audit / User Reflection

在 Shared Foundation、Cluster、大迁移 / Schema Freeze、Stage Closure、用户主动质疑长期方向时执行 Future Explosion Review。

检查规模 5–10 倍后的 linear / quadratic / combinatorial explosion、dual truth、context growth、shotgun change、过度平台化或成本恶化。

涉及产品体验、长期成本与不可逆架构时才邀请用户做 Owner Reflection。

---

# 16. Machine Binding Boundary

G9 前不冻结 JSON / Schema、Router API、Runtime API、retrieval algorithm、token budget、Creator machine field、Bundle machine contract。

G8-WEB-04 Final Host Convergence 已 PASS / CLOSED，但 G8 Exit 尚未完成；G9 machine schema / compiler / Router 仍必须等待 G8 Exit。

# 19. 最终维护原则

> **先维护 Canonical Mechanism，再让世界消费；先保证 Runtime 可以局部激活，再允许资产生态继续扩张。世界可以越来越复杂，但模型不应因此每 Turn 重读整个世界。**
