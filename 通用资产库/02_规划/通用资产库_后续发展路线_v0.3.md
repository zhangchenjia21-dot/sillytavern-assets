# 4. Runtime Context Orchestration｜所有后续资产前提

冻结：

```text
Available != Enabled != Runtime Relevant != Model Visible
Full Asset != Prompt Payload
Dependency Graph != Context Inclusion Graph
```

Router：

```text
Player Input
+
Enabled Routing Profiles
+
minimal current context
↓
Model-first Semantic Router
↓
immediate Domain / Intent candidates
↓
Program structural validation + state-mandatory augmentation
↓
JIT bounded projection
```

后续后果通过 Formal Event / Handoff 激活，不要求 Router 预测全世界因果。

Pattern：`[[通用资产库_RuntimeContextContract模式_v0.1]]`。

核心趋势：

```text
Enabled Assets ↑↑↑
ordinary unrelated Turn context ≈ stable
```

```text

ordinary Turn context ≈ bounded
```

# 6. Generic Library Identity Normalization

仍需 Magic / Divine / Combat Magic 去除首发世界作为资产身份、诸界余辉保留 reference consumer、blueprint 统一指向 Generic Library。

可与 Wave 3 / Wave 4 Context Retrofit 合并执行，避免重复版本 churn。

---

# 7. Future Magic Theme Slots

仍按真实需求再生产：空间与位面、预言与命运、元素与毁灭、心灵与幻象、灵魂与亡灵、生命与变形、法术研究与创造、魔法工艺与魔具。

不得为了“库看起来完整”提前填槽。

---

# 8. 暂缓 Supporting Domains

当前不主动抽医学专门玩法、毒素 /炼金、制造 /工艺、载具 /航海、商业专门玩法、科举、教育、宗教组织、地产、犯罪、情报、工程、派系。

除非真实消费者证明现有 Owner 无法承载。

---

# 9. G9 Rebinding Priority

G9 按上游 / Context 风险，不按资产数量推进：Context Retrofit stable foundations → Remaining Shared Foundation → Generic Gameplay / Framework → Supernatural Core → Theme。

实际顺序服从真实 Host / Runtime Capability。

---

# 10. Architecture Reflection

每个 Retrofit Wave / Shared Foundation Cluster 结束后执行 Future Explosion Review：Context 是否随无关资产增长、是否出现 state mirroring、是否误把依赖展开成 Prompt、是否过度拆模块、是否需要用户做成本 /长期体验反思。
