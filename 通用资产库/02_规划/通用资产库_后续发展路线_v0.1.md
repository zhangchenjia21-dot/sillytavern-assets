# 2. 下一次最值得做的维护工作

## M1｜Generic Library Identity Normalization

对象：

- 魔法基础
- 神术与信仰
- 战斗魔法

目标：

- 从“诸界余辉首发资产”彻底迁移为通用库资产；
- 诸界余辉降为 reference consumer；
- blueprint 统一指向通用资产库；
- 保留世界兼容说明，但不再把世界绑定写进资产身份。

---

## M2｜统一 Generic Metadata

等 G9 前最后一次 Semantic 收敛时，建议所有通用资产人工管理 Frontmatter 至少统一记录：

- asset id / alias；
- version；
- status；
- library tier；
- dependency role；
- hard dependencies；
- optional integrations；
- conditional dependencies；
- reference world consumers；
- UI ownership / contribution summary；
- creator binding；
- asset-spec binding；
- supersedes。

注意：

> 这是当前 Markdown 管理约定，不是 asset-spec Schema。

---

# 6. Creator 维护目标

未来 Creator 的“通用资产库”应至少支持：

- Library Browser；
- Dependency Graph；
- Owner Registry；
- Consumer World list；
- Upgrade impact；
- Theme / Core 分类；
- Surface Ownership；
-批量验证；
- Version drift；
- Asset Family composition。

Creator 不应把“World Pack 项目文件夹”作为通用资产唯一归宿。

---

# 7. 重新评估条件

当以下条件出现时更新本路线：

- G8 Host 新增 / 删除正式 Capability；
- G9 vNext 机器协议冻结；
- 新世界至少第二次消费 Magic / Divine / Combat Magic；
- 出现两个世界都需要同一个尚不存在的机制；
- 当前 Theme 数量显著增加；
- Creator Asset Library Workspace 成型。
